# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ECTO (Environmental Conditions, Treatments and Exposures Ontology) is a composite ontology that assembles existing OBO ontologies (ExO, CHEBI, ENVO, etc.) to create pre-composed classes for describing experimental treatments, environmental exposures, and stimuli for any organism.

**Key design principles:**
- Species-neutral (suitable for any organism, not just model organisms)
- Neutral to experimental vs clinical context
- Pattern-driven: most classes are generated from DOSDP patterns + TSV data, not manually edited

## Build Commands

All commands run from `src/ontology/` directory using the ODK Docker container:

```bash
# Full release build (45-90 minutes)
sh run.sh make prepare_release -B

# Fast release (skip imports, patterns, mirrors)
sh run.sh make prepare_release_fast

# Run tests
sh run.sh make test

# Fast tests (no import refresh)
sh run.sh make test IMP=false PAT=false MIR=false

# Build patterns only
sh run.sh make patterns

# Refresh all imports
sh run.sh make refresh-imports

# Refresh single import (e.g., chebi)
sh run.sh make refresh-chebi

# Generate components
sh run.sh make all_components

# Compare local changes to current release
sh run.sh make feature_diff
```

**Build flags:**
- `IMP=false` - skip import regeneration
- `MIR=false` - skip mirror downloads
- `PAT=false` - skip pattern regeneration
- `COMP=false` - skip component regeneration

## Project Architecture

```
src/ontology/
├── ecto-edit.owl          # Main editable ontology source (edit this)
├── Makefile               # Generated by ODK - DO NOT EDIT
├── ecto.Makefile          # Custom ECTO overrides (edit this for new rules)
├── ecto-odk.yaml          # ODK configuration
├── run.sh                 # Docker wrapper for builds
├── imports/               # Generated import modules (14 ontologies)
└── components/            # Generated component modules

src/patterns/
├── dosdp-patterns/        # YAML pattern templates (34 patterns)
└── data/default/          # TSV data files for pattern instantiation
```

## Adding/Modifying Terms

**Pattern-based terms (most common):**
1. Edit the appropriate TSV file in `src/patterns/data/default/`
2. Run `sh run.sh make patterns` to regenerate

**Core ontology terms:**
1. Edit `src/ontology/ecto-edit.owl` in Protege

**Deprecating terms:**
1. Delete the term from the pattern TSV in `src/patterns/data/default/`
2. Add a row to `src/templates/obsolete.tsv`
3. Run `sh run.sh make templates components/obsoletes.owl`

## Release Process

1. Ensure all PRs merged and CI passes
2. Create release branch: `ecto-release-YYYYMMDD`
3. Run: `sh run.sh make prepare_release -B`
4. Sanity check `ecto.owl` in Protege
5. Commit, push, create PR, merge to master
6. Create GitHub release with tag `vYYYY-MM-DD` (must match data-version in ecto.obo)

**Important:** No more than one release per day.

## Querying the Ontology

Search for terms in the main OWL file:
```bash
# Find a specific term by ID
grep -n "ECTO_NNNNNNN" src/ontology/ecto-edit.owl

# Search by label
grep -n "exposure to benzene" src/ontology/ecto-edit.owl

# Search pattern TSV data
grep -rn "search_term" src/patterns/data/default/

# Use runoak for structured queries (if installed)
runoak -i src/ontology/ecto-edit.owl info ECTO:NNNNNNN
```

## AI Agent Usage

ECTO includes specialized AI agents in `.claude/agents/` for ontology curation:

- **task-coordinator** — Start here for ANY ontology work; plans the full workflow
- **design-pattern-advisor** — Identifies applicable DOSDP patterns before term creation
- **deep-research-specialist** — Literature review and evidence gathering
- **identifier-validator** — Validates CHEBI, ENVO, UBERON, PMID identifiers
- **metadata-checker** — Verifies metadata compliance after term creation
- **ontology-reasoner** — Validates OWL logical consistency

### Critical Rules for AI-Assisted Curation

- **Never guess identifiers** of any kind — verify CHEBI, ENVO, UBERON, ECTO IDs, and PMIDs
- **Always check patterns first**: use `design-pattern-advisor` before creating any new term
- **All definitions require citations**: format as `PMID:NNNNNNN` in `hasDbXref`
- **AI-created terms** must include creator attribution: `dc:creator: https://ai4curation.github.io/aidocs/reference/clients/claude-code/`
- **Pattern-generated terms** go in TSV files (`src/patterns/data/default/`), not `ecto-edit.owl`
- **Never edit generated files**: imports/, components/, and the main Makefile are auto-generated

### Analyse Issue Skill

Use `/analyse-issue [NUMBER]` to generate a structured analysis of a GitHub issue including validity assessment, applicable patterns, proposed term details, and supporting literature.
